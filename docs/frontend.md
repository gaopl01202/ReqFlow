# 前端与 Ant Design 规范

> 当前实现基线（2026-10-26）：前端为 React/TypeScript/Vite/Ant Design；工作项只保留需求、任务、缺陷三个列表Tab及分类侧栏，没有看板切换；所有列表使用手动“搜索”提交及重置，右侧操作列只在存在操作时出现。工作项详情中项目写权限成员均可编辑，删除限创建人/项目管理员；处理人只在提交流转或重新激活时校验。项目文档以文件夹/上传为入口，预览使用本地按需加载的 File Viewer。下文按 UI 编号保存具体实现记录；较早的编号记录可能描述当时的实现，若与当前基线或业务说明冲突，以当前规则及后续明确标注的修订为准。

## 1. 采用方式

使用 React + TypeScript + Vite，安装官方 `antd` 包并锁定版本。**不下载第三方“AntD 风格 Markdown”作为真值**：此类文件容易与实际组件版本和 API 脱节。本文件只规定 ReqFlow 的产品层用法，组件属性、主题 token、中文本地化以 [Ant Design 官方入门](https://ant.design/docs/react/getting-started/)、[主题定制](https://ant.design/docs/react/customize-theme/) 和 [国际化](https://ant.design/docs/react/i18n/)为准。升级 antd 时先核对官方迁移说明并做视觉回归。

## 2. 全局视觉

- 页面采用 Ant Design 的布局、表格、表单、弹窗、抽屉、标签、提示和空状态组件；不自行仿制已有基础组件。
- 应用布局限制在浏览器视口内，顶部条固定在右侧布局顶部，不随内容滚动；左侧品牌固定、菜单独立纵向滚动；项目切换位于顶部左侧；右侧内容区独立滚动，两侧滚动不传递到整个页面。页面标题不再显示冗余的“REQFLOW / WORKSPACE”或项目编码眉题。
- 顶部导航与左侧项目导航保持稳定。页面内容最大宽度、留白、字号、圆角和颜色通过 `ConfigProvider.theme.token` 及少量项目 CSS 统一管理，禁止每页自行写一套颜色与间距。
- 默认使用官方浅色风格和蓝色主色；无品牌色决策前不自造大面积视觉主题。语义色：危险操作用错误色、提醒用警告色、成功用成功色，不能仅靠颜色传达状态。
- 应用入口设置 `ConfigProvider` 中文语言包与统一日期 locale，并使用 Ant Design `App` 承载 message、modal、notification 上下文。所有日期按北京时间显示。
- 桌面端优先，目标宽度 1280px 及以上；窄屏时表格可横向滚动，不让操作列被裁掉。键盘焦点、表单标签与错误文本可见。

## 3. 页面模式

| 场景                   | 组件模式                                          | 约定                                                                                                  |
| ---------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 项目与工作项列表       | `Table` + 筛选 `Form`                             | 默认 20/页；编号/标题可进入详情；筛选、分页与 URL 查询参数同步。                                      |
| 简单配置新建、编辑     | `Modal` + `Form`                                  | 与示例一致，居中弹窗；保存失败保留输入，保存成功关闭并刷新列表。                                      |
| 工作项新建、编辑和详情 | 独立页面 + `Card`、`Form`、`Descriptions`、`Tabs` | 需求、任务、缺陷不使用弹窗或抽屉；支持地址刷新、浏览器前进/后退和返回列表，详情包含评论、附件与历史。 |
| 删除、停用、关闭       | `Modal.confirm` 或等效确认                        | 写清对象、影响和不可逆之处；取消不产生请求。                                                          |
| 状态、优先级           | `Tag`                                             | 颜色统一来自配置；同时显示文字。                                                                      |
| 工作项状态流转         | 工作项详情的状态选择、处理人和评论                | 工作项仅列表；流转和重新激活均使用服务端工作流配置及授权校验。                                          |
| 反馈                   | `message`、`Alert`、`Result`                      | 成功轻提示；字段错误贴近字段；整页错误有重试入口。                                                    |
| 空数据与加载           | `Empty`、`Skeleton`、表格 loading                 | 区分无数据、筛选无结果、无权限、加载失败。                                                            |

## 4. 表单与交互规则

- 必填项在标签和校验中一致；前端校验长度、格式与日期顺序，服务端返回的 `fields` 错误映射到对应表单项。
- 提交按钮请求期间禁用并显示 loading，防重复提交。二次确认只覆盖一次具体操作，不长期存储“已确认”状态。
- 列表操作按钮按权限显示；无权限的 API 响应仍要能正确处理。并发冲突提示“数据已更新，请刷新后重试”，保留未提交输入供复制。
- 列表默认排序与业务说明一致；列值缺失显示“—”。时间、状态、负责人名称在列表、详情、报表口径一致。
- 重置密码的临时密码只在本次响应内存中显示，关闭即清除；不写入 URL、localStorage、埋点或错误日志。浏览器阻止新窗口时使用当前页一次性弹窗。
- 不把内部错误堆栈、数据库 ID 或实现细节作为给用户的提示文案。
- API 客户端兼容统一 JSON 错误体；代理或服务异常返回空/非 JSON 内容时，显示通用可读提示，不向页面抛出 JSON 解析异常。

## 5. 实现与验证

前端目录建议：`src/app`（路由、布局、Provider）、`src/features/<module>`（页面与状态）、`src/components`（确实复用的组件）、`src/api`（类型化客户端）、`src/styles`（全局 token 与少量 CSS）。API 类型优先从 OpenAPI 生成，避免手写两套字段。页面至少检查列表、表单、空状态、权限拒绝、错误反馈和 1280px 桌面布局。

## 6. 当前实现

React/TypeScript/Vite 与官方 Ant Design 已安装锁定；中文 ConfigProvider、统一蓝色 token、居中 Modal、工作项独立页面、分页 Table、报告与工作项分类列表已接入（UI-47取消前端看板）。正文使用 ReactMarkdown 渲染 Markdown，经 rehype-raw/rehype-sanitize 白名单过滤 HTML，span 仅放行十六进制文字颜色样式，URL 使用组件默认过滤，不执行脚本。主要路由及分页、搜索、筛选同步到 URL 查询参数，模块切换重置。最近访问只在本地保存项目 ID，展示时再次与当前可见项目相交。时间字段通过 Intl 的 Asia/Shanghai 显示。API 客户端集中处理同源 Cookie、CSRF 与统一错误；src/generated/api.d.ts 由 OpenAPI 生成，当前用户类型直接引用生成契约。

工作项分类侧栏中，分类名称默认可使用整行宽度显示；仅当存在分类管理操作并悬停或聚焦该行时，才为编辑/删除图标预留空间，避免未显示操作按钮时文字提前截断。

所有表单失败保留内容；后端 fields 映射 Form.Item。临时密码只存 React 内存，关闭窗口清除。文档与工作项附件均走鉴权接口。批量操作显示成功数和逐项失败原因。工作项工作流仅在详情中操作，缺少处理人时在提交时提示；工作流与选项由服务端验证，前端权限只用于操作可见性。

浏览器测试文件位于 frontend/e2e，具体覆盖与结果见 verification.md。

## 7. 职务与优先级拖动排序

两类配置的新建/编辑表单、列表均移除排序数值。管理员列表显示左侧拖动手柄；支持拖到目标行前/后，插入线提示位置，松开自动提交，提交中禁用重复拖动。也支持聚焦手柄后用上下方向键调整。搜索中禁用拖动；分页内拖动保存全局相对位置。失败不预先改动列表，显示原因并刷新；成功刷新当前页及下拉选项。优先级上方表示更高优先级。分类也使用相同拖动交互，但按项目范围保存并限制项目管理员；分类不再提供数字排序输入。工作流状态列同样通过拖动调整，需点击保存工作流提交。

## 8. 整体样式与独立页面（UI-01～04）

参照 Ant Design Pro 的查询表格与高级详情页，采用240px浅色侧栏、56px顶部条、灰色背景、白色内容卡片、16px/600列表工具栏标题、20px编辑页标题、14px正文与统一24px留白。筛选区与表格分区，操作按钮使用轻量文字样式。既有视口内固定顶部、独立滚动结构保留。

人员入口为头像与姓名下拉菜单，仅有修改密码和退出登录；移除个人改名页面及接口。装饰图标不进入可访问名称。日期统一 `ChineseDateInput`（官方 DatePicker + ConfigProvider 中文 locale + dayjs zh-cn），展示/传输 YYYY-MM-DD；不使用浏览器原生日期控件。颜色选择使用中文名称和色点预览，所有优先级展示使用 `PriorityTag`。

列表为字段指定合理列宽，对长文本省略提示，操作列 `fixed: right` 且指定宽度；表格内横向滚动不会把操作列移走。工作项表单使用左侧标题/富文本正文、右侧属性的布局，小屏自动单列。基础组件与主题均使用已锁定官方 Ant Design 包。

新建工作项地址仍使用query参数保留分类等默认值；工作项详情/编辑现采用UI-74的可读路径，旧item_mode/item_type/item_id详情地址保留兼容。地址可直接打开、刷新恢复，浏览器前进/后退与页面状态同步；保存后进入详情，原列表标签页保持模块与筛选；独立分享页返回列表使用默认筛选。列表/看板快捷流转的处理人选择仍使用确认弹窗。项目文档也使用独立的全屏内容页；迭代辅助详情保留抽屉。

src/ui.tsx 集中共享表单、日期、优先级颜色及中文显示映射，避免在不同页面重复写一套组件规则。

## 9. 导航、紧凑列表与可视化编辑（UI-05～08）

顶部左侧为突出名称且带“切换项目”提示的项目选择器，支持输入搜索及键盘选择；登录后按当前浏览器、账号恢复最近访问且仍有权限的项目。右侧铃铛进入站内通知，侧栏移除通知和独立看板入口。工作项只保留需求/任务/缺陷页签与列表，列表左侧常显分类导航；不保存看板视图偏好。工作项项目概况通过列表标题旁入口查看，包含简介、负责人、成员数、计划日期、工作项数量、逾期与当前迭代。

筛选默认只显示一行，内容换行时显示展开/收起；所有列表筛选都有显式“搜索”按钮，点击后才发起查询，“重置”始终显示在最右，文本框可独立清除。列表标题和新建位于表格工具栏，所有列表不显示刷新按钮；操作列固定右侧并保持紧凑，若无行操作则整列隐藏。表格行上下间距紧凑。最近项目为展示名称和成员数量的卡片；统计卡片同排等高。

src/rich-editor.tsx 使用 Vditor 即时渲染（IR）编辑器，阅读端使用 remark-gfm；工作项描述支持格式工具栏、Markdown 语法即时排版、剪贴板粘贴图片和拖入图片。标题/正文在左侧，属性在右侧以标签/控件左右排列，附件紧接左侧正文下方；保存/取消固定在工作区视口底部。文档新建/编辑/查看同样使用独立页面，正文默认可视化 Markdown；旧 Markdown 可继续查看和编辑，HTML 不执行。图片和附件暂存于内存，保存时通过 multipart 与记录原子提交，取消不会上传；保存失败保留输入与待提交文件。图片使用有权限检查的 inline 附件地址；附件下载、删除仍走既有接口。图片预览对象地址在离开编辑时释放，不持久化正文到 localStorage。

## 10. 新建页紧凑布局（UI-09）

标题输入框在默认、悬停、聚焦和校验状态下仅有底边，不使用四周聚焦阴影。RecordForm 的编辑主栏和属性栏为独立容器：左侧标题与 Markdown 描述按顺序排列，描述撑满可用区域；附件位于右侧属性下方并以分隔线区分。右侧标签和输入控件水平对齐，长文本属性使用紧凑文本域。附件随右侧属性区域滚动。

描述默认使用 Vditor 的 Markdown 即时渲染模式，无旧“编辑/Markdown”模式切换。支持 Markdown 标题、粗体、列表、表格及图片粘贴/拖入，保存仍使用既有 Markdown 与原子附件契约。编辑器缓存关闭，运行时、中文和图标资源均由锁定 npm 包复制到同源 public/vendor/vditor，dev/build 前自动同步，不从 CDN 加载、不向第三方传送正文。

工作项和文档编辑页只有一套保存/取消操作，固定于右侧工作区视口底部；内容区预留底部空间，长表单滚动和矮视口不会遮挡最后字段或附件。只调整前端，无接口、权限或迁移变化。

## 11. 编辑与详情统一工作区（UI-10～12）

编辑页去除顶部新建/编辑标题和返回列表按钮，取消操作仍固定底部；标题保留必填校验但不显示标签，输入框提示“请输入标题”。工作项描述去必填与标签，IR 编辑器提示“请输入描述”；优先级默认中、无必填标记，其他类型专属必填项不变。文档正文仍按文档规则必填。

工作项详情由 src/work-detail.tsx 展示：标题栏包含当前状态、标题、编号、编辑/删除图标以及返回图标；图标有中文可访问名称且保持权限/确认。标题下方为独立的左内容和右属性栏：描述、附件、评论/历史、工作流各有分隔线；右侧 label/value 两端水平对齐。整页固定在内容视口中，左右各自 overflow:auto，右侧足够高时不会随左侧滚动。编辑页也使用两个独立滚动栏，不会因长正文带动右侧属性。

工作流区域展示当前状态与允许到达的阶段选择；UI-17 起仅保留多选处理人和富文本评论。确认流转按钮固定底部，提交期间 loading，失败保留输入；成功刷新状态、评论和历史。只显示既有工作项、附件、评论、历史和流转能力，不增加模板、复制、导出等未实现入口。普通列表/看板的快捷状态命令仍保留原确认方式。

## 12. 详情完整编辑入口（UI-13）

工作项详情的编辑按钮直接按记录 type 打开完整编辑表单，不依赖当前菜单 screen。具有项目写权限的成员从工作台、通知或详情地址进入时，均可编辑标题、Markdown 描述、优先级、负责人、分类、迭代、日期及该类型已有的专属字段，并可添加附件；编号、类型、创建人和历史仍只读。工作项列表不显示编辑入口；删除仅显示给创建人和项目管理员。文档详情同样由 editDocument 直接打开标题/正文完整编辑，避免误入配置表单。沿用服务端权限、版本号和工作项 PATCH/multipart 接口，无后端和迁移变更。

## 13. 附件多选与单文件错误隔离（UI-14）

共享 AttachmentPicker 使用官方 Upload multiple，一次选择仅处理一次完整 fileList，避免 beforeUpload 每文件回调造成重复上传。逐个检查当前用户返回的 attachment_max_bytes 与 attachment_extensions；大小等于上限允许，超出者跳过，合并提示文件名与具体原因。新建/编辑只暂存合法文件（最多20个/次保存，超过剩余数量的单独提示），不因选择中含超限文件而让全部保存失败；描述粘贴图片继续复用同一文件校验。

详情合法文件按顺序调用既有单文件鉴权上传 API，个别服务端失败提示该文件并继续下一项。批次完成统一拉取附件列表，避免每个请求刷新整个详情导致批次中断或未提交评论丢失；上传期间按钮 loading/禁用。全部无效时不发请求，不改变已有附件。工作项附件允许格式及单文件上限由 `/auth/me` 返回，具体清单见 `docs/attachment-formats.md`；格式按需加载浏览器预览，项目文档上传仍使用其独立清单。其余服务端权限、大小、审计及原子保存规则不变。

## 14. 详情附件、评论与流转（UI-15～17）

附件为可折叠浅灰文件行，显示名称、图标、下载/删除及上传者和时间；加号复用多选过滤。评论为可折叠区域，标题加号展开 compact Vditor IR 编辑器，支持粘贴图片；内联编辑同样使用富文本。评论第一行为姓名及提交时工作流状态快照，第二行正文，右侧时间和图标操作；无 @ 选择。添加/编辑后只刷新评论与附件，不清空其他草稿。描述/评论内联图片通过后端持久标记与独立附件区分，正文编辑移除图片后也不会变成附件行。

流转只提供阶段、处理人多选（必填且星号在文字右侧）和紧凑富文本评论；移除通知成员、原因、子任务确认。处理人初始为空时不标红、不禁用流转按钮；点击确认流转或重新激活时进行必填校验并提示，后端仍强制验证。旧 assignee 编辑入口变更时替换处理人集合，未变更时保留多处理人；详情和列表显示所有处理人。项目负责人保持单选。

## 15. 表头与数据行间距（UI-18）

所有 Ant Design 表格的紧凑纵向 padding 仅作用于真实数据行（排除 .ant-table-measure-row），不覆盖组件用于计算列宽的零高测量单元格；禁止通过 display:none 移除测量行。表头底部与第一条数据行顶部直接衔接，横向滚动和固定操作列保持有效。共享样式覆盖所有列表、报表和迭代抽屉表格，无接口/业务规则/数据迁移变化。

## 16. 详情密度与评论顺序（UI-19）
